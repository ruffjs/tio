# TIO Broker 监控方案

在 TIO Web 中查看内嵌 NATS 的消息吞吐、MQTT 连接及实际订阅，以及 MQTT 消息 stream 的 consumer 用量。值班人员可以先按时间定位吞吐变化，再通过 Client ID 核对设备连接和下行订阅。

## 导航与页面

在左侧主菜单「规则」下方增加「Broker 监控」，路由为 `/broker`，沿用现有登录流程。原 MQTT 工具的仪表盘按钮在上线时移除。

| 区域 | 内容 |
|---|---|
| 概览 | 当前节点名称、NATS 版本、采样时间、在线 MQTT 连接数、`$MQTT_msgs` 的 consumer 用量和生效上限。 |
| 吞吐趋势 | 最近 1 小时的收发消息数每秒和字节数每秒。以两组曲线分别显示消息速率和字节速率，并标明单位与数据范围。 |
| 连接列表 | Client ID、连接时间、最近活动、收发消息数和订阅数。支持按 Client ID 查找、按订阅数排序，以及「全部 / 无订阅 / 有订阅」筛选。 |
| 连接详情 | 点击一行打开抽屉，显示这条连接的订阅列表。保留 NATS 返回的原始 subject，并将 `$MQTT.sub.*` 等内部订阅单列，方便核对设备方法和 shadow 下行。 |

订阅数为 `0` 时按普通数值展示，仅用于筛选和排序。页面注明连接及流量指标属于当前节点。

## 数据采集与接口

- **吞吐与概览**。通过内嵌 NATS 的 `Varz` 和 `Jsz` 采样。吞吐使用节点客户端的累计收发消息数和字节数，按相邻样本的差值除以实际间隔。曲线口径为当前节点的客户端流量，包含该节点的 MQTT 和原生 NATS 客户端。
- **历史窗口**。服务端每 15 秒采样一次，内存中保留最近 1 小时。打开页面即可读到已采集的历史。计数重置、进程重启或采样缺失时，曲线留空并标记数据缺口。
- **Consumer 容量**。针对 `TIO_APP` 的 `$MQTT_msgs` 显示当前用量，按实际生效的 stream、账户和服务端限额取值。stream 尚未创建时显示「尚未创建」。上限不限或无法确定时，显示其实际状态。
- **连接与订阅**。使用 `Connz` 查询当前节点的在线 MQTT 连接。列表在服务端先筛选和排序，再分页。详细订阅按连接 ID 点查。连接在查看期间关闭时，详情提示连接已结束，并允许返回列表刷新。

在现有 `/api/v1/mqttBroker` 服务下增加只读接口，复用现有鉴权。由后端从内嵌 NATS 读取数据，并向 Web 返回页面需要的字段。

| 拟新增接口 | 返回数据 |
|---|---|
| `GET /monitor/overview` | 节点概览、consumer 用量与上限、最近一小时的时间序列。 |
| `GET /monitor/connections` | 分页连接列表，接受 Client ID、订阅状态和排序条件。 |
| `GET /monitor/connections/{cid}` | 当前连接及其订阅 subject。 |

第一版提供节点级视图和进程内短期历史。集群汇总、跨重启历史和告警可在需要时另行扩展。

## 实施与验收

1. **接入后端采集和查询**。验证收发计数按实际采样间隔换算，重置与缺样呈现为断点。验证 consumer 生效上限，以及连接过滤、排序和分页结果。
2. **实现监控页和主菜单入口**。验证登录后可从主菜单打开或刷新 `/broker`，图表显示单位与节点，连接详情可查看实际 subject。
3. **用本地 MQTT 流量验收**。两个客户端都持续上报，其中一个订阅方法和 shadow 下行，另一个保持零订阅。页面应显示吞吐变化、准确筛出零订阅连接，并在对应详情中看到实际下行订阅。再用现有压测方案验证 10,000 台连接下的采样开销、分页与单条详情查询。
